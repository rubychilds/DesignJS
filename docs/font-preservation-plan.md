# Font preservation in captured pages — phased plan

**Status:** Phase 1 WIP on side branch (`f1-google-fonts-fallback`, commit `5c2a58b`). Sync script + bundled 1,934-family manifest + extractor / resolver module land there; remaining work before merge: tests per §D + end-to-end verification per §E. Phases 2 + 3 deferred.

Working doc tracking the multi-phase improvement to how captured pages preserve their original web fonts. Extends [epic-8-followups §3.1](./epic-8-followups.md#31--google-fonts--external-font-face-missing-high-impact) (CDN `<link>` allowlist, shipped 2026-04-25) by covering the cases the allowlist doesn't reach.

## Context

Today the capture pipeline preserves a font only when the source page loads it via a `<link>` to one of four allowlisted CDNs (Google Fonts, Bunny Fonts, Typekit). For everything else, the captured `font-family` value is correct but the actual font file never loads, so text renders in the system fallback. Verified live: capturing the Wikipedia "Love" article shows `"GT Flexa Standard"` and `"NB International Pro"` in the captured CSS, but only fonts loaded via `<link>` make it across.

User asked for three improvements, ordered:

1. **Identify font names → fall back to Google Fonts CDN** when the name matches a known Google Fonts family (Onlook's pattern)
2. **Download font binaries at capture time** and base64-embed in `@font-face` (SingleFile's pattern) — for fonts whose URL is reachable
3. **Local desktop fonts** (Penpot/Figma installer pattern) — deferred follow-up

This doc covers Phase 1 in detail, sketches Phase 2 at a higher level, and reserves Phase 3 as a placeholder.

### Peer-tool comparison

| Tool | Strategy |
|---|---|
| **SingleFile** (AGPL) | Download `.woff2` at capture; embed in CSS (base64 or archive file ref). [`processor-helper-inline.js:287-305`](../SingleFile/node_modules/single-file-core/core/lib/processor-helper-inline.js) |
| **Onlook** (Apache-2.0) | Identify by name, inject Google Fonts `<link>` if matched. Cleans Next.js `__Inter_Fallback_abc123` style suffixes. [`use-font-loader.tsx:6-12`](../onlook/apps/web/client/src/hooks/use-font-loader.tsx) |
| **Penpot** (MPL-2.0) | Match font-family to user's team font library; prompt user to upload missing fonts. No CDN auto-fallback. ([Issue #5195](https://github.com/penpot/penpot/issues/5195)) |
| **Blipshot / Screenshot Capture** | Pixel-only — N/A. |
| **DesignJS today** | `<link>` preservation for CDN allowlist + computed `font-family` inline + same-origin `@font-face` author CSS. |

### Decisions

- **Missing-font UX (when no GFonts match):** silent CSS fallback (no inspector badge, no console warning). Matches Onlook's behavior; minimizes scope. Penpot-style "missing fonts" UI can come with Phase 3.
- **Google Fonts list:** bundled JSON, generated by a one-shot script committed to repo. Deterministic builds; offline-safe.

## Today's pipeline (anchor facts)

- [`collectFontLinks(head)`](../packages/chrome-extension/src/capture/style-serializer.ts) extracts `<link rel="stylesheet">` whose hostname is in `FONT_LINK_HOSTS`, returns dedup'd HTML.
- [`content/index.tsx:302-307`](../packages/chrome-extension/src/content/index.tsx) splices the result immediately after the outer `<div>`'s opening tag, before the captured DOM and `<style>` blocks.
- [`collectAuthorCss(doc)`](../packages/chrome-extension/src/capture/style-serializer.ts) walks `document.styleSheets`, includes `@font-face` from same-origin sheets, rewrites relative `url()` via [`absolutizeCssUrls`](../packages/chrome-extension/src/capture/style-serializer.ts).
- Per-element computed `font-family` is captured via the `INHERITED_DIFF` list in inline mode.
- No first-family extractor exists yet — [`TypographySection.tsx`](../packages/app/src/components/inspector/TypographySection.tsx) reads the raw CSS value and matches against presets but does no parsing.
- Existing tests: `style-serializer.font-links.test.ts` (allowlist + dedup), `style-serializer.author-css.test.ts` (@font-face from same-origin) — same patterns to follow for new tests.

## Phase 1 — Google Fonts name fallback

### A. Bundled Google Fonts manifest

- **New file**: `scripts/sync-google-fonts.mjs` — fetches `https://fonts.google.com/metadata/fonts` (no API key needed), extracts `family` + available weights, writes:
  ```
  packages/chrome-extension/src/capture/google-fonts.json
  ```
- **Shape**: `{ "Inter": [100,200,300,400,500,600,700,800,900], "Roboto": [...], ... }` — family → available weights array. Expected size ~30-50KB minified.
- **Cadence**: manual (`node scripts/sync-google-fonts.mjs`). The committed JSON survives offline builds. Re-run when a refresh is wanted (e.g. quarterly).

### B. New module: `packages/chrome-extension/src/capture/google-fonts.ts`

Three exported functions:

1. **`extractFontFamilyNames(cssValue: string): string[]`**
   - Splits on top-level `,`, trims, strips matching `"` / `'`.
   - Filters CSS generic names: `serif`, `sans-serif`, `monospace`, `cursive`, `fantasy`, `system-ui`, `ui-serif`, `ui-sans-serif`, `ui-monospace`, `ui-rounded`, `math`, `emoji`, `fangsong`, `-apple-system`, `BlinkMacSystemFont`, `none`, `inherit`, `initial`, `unset`, `revert`.
   - Strips Next.js / CSS Modules generated suffixes: regex `/^__|_Fallback_|_[a-f0-9]{6,}$/`. (See Onlook's [`use-font-loader.tsx:6-12`](../onlook/apps/web/client/src/hooks/use-font-loader.tsx).)
   - Returns deduped list preserving order.

2. **`resolveGoogleFonts(familyNames: string[], weightsByFamily: Map<string,Set<number>>): string | null`**
   - For each name, lowercase-and-hyphen-normalized lookup against bundled manifest (e.g. `gt flexa` won't match `GT Flexa Standard` because not on GFonts; `inter` matches `Inter`).
   - For matched families, intersect requested weights with available weights; if no weights requested, default to `[400, 700]`.
   - Builds a single `css2` URL: `https://fonts.googleapis.com/css2?family=Inter:wght@400;500;700&family=Roboto:wght@300;400&display=swap`.
   - Returns the `<link>` HTML string, or `null` when no matches.

3. **`collectGoogleFontRequests(root: Element): Map<string, Set<number>>`**
   - Walks the captured DOM, reads each element's computed `font-family` + `font-weight`.
   - Builds map `requested-name → set-of-weights` for input to `resolveGoogleFonts`.

### C. Integration

In [`style-serializer.ts`](../packages/chrome-extension/src/capture/style-serializer.ts):
- Export a new `collectGoogleFontsLink(rootElement, document): string` that composes B1 + B2 + B3. Same shape as `collectFontLinks` (HTML string, empty when no matches).
- Skip names already covered by a `<link>` in the source page's `<head>` to avoid duplicate requests (re-use the URL parse from `collectFontLinks`).

In [`content/index.tsx`](../packages/chrome-extension/src/content/index.tsx) around line 302:
- Call `collectGoogleFontsLink(...)` alongside existing `collectFontLinks`.
- Splice both into the captured HTML at the existing splice point. Concat order: CDN links first (user-explicit), Google Fonts fallback second.

### D. Tests

New file: `packages/chrome-extension/src/capture/__tests__/google-fonts.test.ts`. Follow the pattern of [`style-serializer.font-links.test.ts`](../packages/chrome-extension/src/capture/__tests__/style-serializer.font-links.test.ts).

Cases:
- `extractFontFamilyNames`: handles quoted/unquoted, strips generics, strips `__Inter_Fallback_abc123`-style suffixes.
- `resolveGoogleFonts`: matched name with default weights; matched name with explicit weights; multiple families combined into one URL; unmatched name returns null; empty input returns null.
- `collectGoogleFontsLink`: end-to-end with a fixture DOM that uses `Inter` and `system-ui` — output contains `family=Inter`, doesn't contain `system-ui`.
- Dedup: family already requested via `collectFontLinks` is not re-emitted.

### E. Verification (end-to-end)

1. `pnpm test` in `packages/chrome-extension/` — all green.
2. `node scripts/sync-google-fonts.mjs` — produces `google-fonts.json` with ≥1,500 entries.
3. `pnpm dev` at repo root → reload extension in `chrome://extensions` → capture a page that uses a Google Font but doesn't have a direct `fonts.googleapis.com` link (Tailwind landing pages bake Inter into CSS without an explicit link — good target).
4. Inspect the captured iframe's `document.fonts` — the Google Font should show `status: "loaded"`.
5. Side-by-side visual diff with the source page — heading and body text should match in family + weight.

## Phase 2 — SingleFile-style font download (separate PR)

For fonts that DON'T match a Google Fonts family but DO have a reachable URL:

- New module `packages/chrome-extension/src/capture/font-inliner.ts`.
- During capture, walk all `@font-face` rules in `collectAuthorCss`'s output.
- For each `src: url(...)`:
  - Try `fetch(url)` from the background script (MV3 service worker — bypasses page CORS).
  - On success, base64-encode and rewrite `src: url(data:font/woff2;base64,...) format('woff2')`.
  - On failure (CSP, 403, network), leave original URL in place — the existing absolutize-via-`absolutizeCssUrls` path is the fallback.
- Add capture-options flag `inlineFonts: boolean` (default `true`) so size-sensitive captures can opt out.
- New test fixture: page with self-hosted woff2 → captured HTML contains `data:font/woff2;base64,...`.

Reference (AGPL — paraphrase only, do not copy): [`SingleFile/node_modules/single-file-core/core/lib/processor-helper-inline.js:287-305`](../SingleFile/node_modules/single-file-core/core/lib/processor-helper-inline.js).

Likely needs `host_permissions: ["<all_urls>"]` in the extension manifest to fetch cross-origin from the service worker — confirm when Phase 2 starts.

## Phase 3 — Local desktop fonts (deferred follow-up)

Penpot/Figma-style font library. Two paths:

- **Web-only (Penpot's path):** font upload UI in the canvas app; match captured `font-family` to the user's uploaded fonts.
- **Companion app (Figma's path):** desktop helper that exposes installed system fonts via [Local Font Access API](https://developer.mozilla.org/en-US/docs/Web/API/Local_Font_Access_API) — Chromium-only, requires user permission.

Out of scope until Phases 1 and 2 land. Will get its own plan when prioritized.
